# TTRS 2.0 正式版：雷电安装与使用教程

适用版本：**2.0 系列正式版，内部构建版本 2.0.1**。本教程按维护者指定的既有 `dist/win-unpacked` 程序编写，没有重新编译或加入测试版功能。

维护者反馈：该程序配合指定的步数兼容 v2 APK，在其雷电环境中也能记录步数。这是本机使用反馈，不是任意雷电版本、账号和应用规则的兼容保证；不代表环境识别问题已修复。

## 1. 下载正确的文件

- [2.0 系列正式版 Release](https://github.com/linmiao09/GKD_TakeTwo_monipao/releases/tag/v2.0.1)
- [Windows 程序 ZIP](https://github.com/linmiao09/GKD_TakeTwo_monipao/releases/download/v2.0.1/TTRS-2.0.1-Windows.zip)
- [单独下载配套 APK](https://github.com/linmiao09/GKD_TakeTwo_monipao/releases/download/v2.0.1/app-taketwo2.0.3-stepfix-v2-signed.apk)

下载后完整解压 ZIP。程序包包含“先看这里.txt”“使用教程.html”“软件”目录及许可说明。运行 `软件/TTRS.exe`，保留 EXE 旁边所有文件。不要只搬动 EXE，不要直接从压缩包里启动。

GitHub 自动显示的 **Source code** 是文档仓库快照，不是程序，也不包含 TTRS 源码工程。运行程序不需要源码、Node.js 或 npm。

## 2. 安装雷电模拟器

1. 从[雷电官方网站](https://www.ldmnq.com/)下载并安装 Windows 版模拟器。
2. 记下实际安装位置，例如 `D:\leidian\LDPlayer9`。安装盘和目录可以不同，后面填写你自己的目录。
3. 启动雷电，等安卓桌面完全进入。首次建议只打开一个实例。
4. 如果提示虚拟化未开启，按电脑厂商和雷电官方说明设置 VT / SVM。

这条安装流程不需要 Android Studio，也不需要额外安装 ARM 转译包。不同雷电版本的控制台与 APK 兼容性仍需以实际环境为准，不能把此处教程理解为所有版本均已验证。

多开时参考[雷电官方多开器说明](https://help.ldmnq.com/docs/btJtNt)，后面需要的是实例编号，不是随意填写的设备名称。

## 3. 安装配套 APK

使用 **`app-taketwo2.0.3-stepfix-v2-signed.apk`**，它是 TakeTwo 步数兼容 v2 补丁版，不是原版，也不是旧 v1 补丁。桌面程序版本 2.0.1 与 APK 文件名中的 2.0.3 是不同版本标识。

APK 可以从 Release 单独下载，也可直接取自解压后的：

```text
软件/resources/apk/app-taketwo2.0.3-stepfix-v2-signed.apk
```

把 APK 拖进已启动的雷电窗口，或点击雷电侧边栏“安装 APK”并选择该文件。安装后打开应用，自行登录并授予正常使用所需权限。

APK SHA-256（可与 Release 的 `SHA256SUMS.txt` 核对）：

```text
2dc2f8a3744e3eeed01e445061ffb149aa50bcfff18be8e04d9e1b206f34b5e4
```

如果安装提示签名冲突，先处理需要保留的数据，再决定是否手动卸载原应用。**卸载会清除模拟器里该应用的本地数据。**第三方 APK 的权利、使用及再分发条件独立适用，见 [NOTICE](../NOTICE.txt)。

## 4. 配置 TTRS 的雷电模式

| 界面项目 | 怎么填或操作 |
| --- | --- |
| 选择模拟器 | 选择 **雷电**；首次默认可能是 AVD，必须切换 |
| 雷电安装目录 | 填实际目录，如 `D:\leidian\LDPlayer9`；也支持直接填 `ldconsole.exe` 或 `dnconsole.exe` 的完整路径 |
| 实例索引 | 默认 `0`；多开时填写与雷电多开器对应的编号 |
| 启动雷电 | 启动选中的实例，等待安卓桌面 |
| 预先定位 | 先发送路线起点，再到目标应用确认位置 |

路径应指向包含雷电控制台程序的实际安装目录，而不是桌面快捷方式所在目录。

**注意：**2.0.1 的“步数兼容”检测和安装面板仅在 AVD 模式下显示。雷电模式按上一步通过雷电本身安装 APK，不要套用 2.1.1 的 AVD 检查流程。

## 5. 配置地图与路线

1. 需要在线地图时，在[高德开放平台](https://console.amap.com/)创建 **Web 端（JS API）Key**，取得同一条 Key 对应的安全密钥。
2. 在程序地图设置中完整填写这两项。不要使用 Android 端 Key，也不要混用不同 Key 对应的安全密钥。
3. 2.0.1 **没有“应用并重新加载地图”按钮**。完整填写后，若只有路线和 Logo、没有道路建筑，完全退出并重新打开 TTRS。
4. 使用原操场路线时，点击“恢复默认四点”，保持闭合循环和椭圆跑道选项。
5. 自定义路线先清空默认四点，再搜索地点，按顺序点击地图添加坐标。搜索地点只移动地图，不会自动替换旧路线点。
6. 根据需要设置目标距离、配速等参数，可保存命名路线供以后选择。

椭圆跑道要求闭合路线且恰好四个点。普通开放路线不循环，长度需要达到发送目标。地图显示坐标与内部 WGS-84 坐标由程序转换，不要自行重复转换。

高德官方参考：[申请 Key](https://lbs.amap.com/api/javascript-api-v2/prerequisites)、[安全密钥说明](https://lbs.amap.com/api/javascript-api-v2/guide/abc/jscode)。开通条件、配额和费用以高德官方为准。不要上传个人 Key、安全密钥或用户配置目录。

## 6. 每次使用的顺序

1. 打开雷电并等待桌面，打开 TTRS，核对雷电模式、目录和实例索引。
2. 选择路线，点击“预先定位”，在目标应用内确认起点。
3. 在目标应用中开始测试，再点击 TTRS 的“开始模拟”。
4. 需要中断时使用暂停、继续或停止。TTRS 只控制定位发送，不会替你操作目标应用的计时、结束和保存。
5. 完成后自行在目标应用内处理结果，检查目标应用最终记录，不只看 TTRS 的预计步数。

2.0.1 手动停止后会保留最后进度，重新开始时再重置。本次正式版保留原程序，不包含 2.1.1 的停止清空和地图重载修复。

## 7. 常见问题

**连续定位失败、locate 命令失败：**确认对应实例已进入桌面，实际目录内存在 `ldconsole.exe` 或 `dnconsole.exe`，实例索引与多开器一致。先退出 TTRS，重新启动对应实例后再试。反馈时提供雷电版本、控制台文件名与报错，不要无限重复开始。

**没有步数：**确认使用的是指定 v2 APK、哈希一致，且应用确实取得了定位与距离变化。兼容 APK 在没有可用传感器步数时按实际距离除以 0.75 米回退保存；静止时没有数据不能说明成功或失败。程序面板估算值不是应用最终记录。

**目标应用提示检测到模拟器、作弊或停止计时：**停止本次测试并遵守目标应用规则。设为正式版不代表此前的环境检测问题已修复，没有新增规避检测逻辑。

**地图底图空白：**检查两项高德凭据是否属于同一条 Web JS API Key，检查网络与高德控制台规则，完整退出并重开程序。本版没有测试版的专用重载按钮。

**位置不对或不动：**检查是否选择了正确实例，定位权限是否正常；不要同时播放雷电内的另一条路线。先预先定位并确认，再开始发送。

**切换版本：**[2.1.1 是原生 AVD 测试版](使用教程.md)，不支持雷电。两版放在不同文件夹，切换前退出另一版；可能沿用同一 Windows 用户的配置，切换后重新核对模式、目录与路线。本版没有界面化路线导入导出功能。

**日常启动嫌麻烦：**分别给雷电和 `TTRS.exe` 创建桌面快捷方式，不要把 EXE 单独移出运行目录。

反馈请到 [Issues](https://github.com/linmiao09/GKD_TakeTwo_monipao/issues)，提供 TTRS 和雷电版本、实例编号、错误文字及遮盖隐私后的截图，不要上传账号、密钥和认证文件。
