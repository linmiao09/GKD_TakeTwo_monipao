# TTRS 2.1.1 中文使用教程

本教程适用 Windows x64 与 Android Studio 原生 AVD。首次配置完成后，日常只需启动模拟器和 TTRS。

用户不需要安装 Node.js、npm、源码工程或编译工具。安装 Android Studio 是为了创建和运行官方模拟器，不需要新建 Android 开发项目。

维护日期：2026-10-19。兼容基线为此前验证的 Pixel 3 / Android 9（API 28）/ Google APIs x86_64；其他系统镜像需单独验证。

## 1. 下载与解压

在 [Releases](https://github.com/linmiao09/GKD_TakeTwo_monipao/releases/latest) 的 Assets 中下载 `TTRS-2.1.1-Windows.zip`，完整解压，例如放到 `D:\TTRS`。

程序入口是 `软件\TTRS.exe`。保留同目录全部文件，不能只复制 EXE，也不要在压缩软件中直接运行。GitHub 自动生成的 Source code 附件只是文档快照，不是程序。

## 2. 电脑准备

- Windows 10 / 11，64 位 Intel 或 AMD x64 电脑。
- 运行 Android Studio 与 Emulator，当前官方要求至少 16 GB 内存及 16 GB 可用空间；建议为下载和模拟器数据预留约 30 GB。
- 任务管理器 → 性能 → CPU，确认“虚拟化：已启用”。未启用时，按电脑厂商说明在 BIOS / UEFI 开启 VT-x 或 SVM / AMD-V。
- Windows 搜索“启用或关闭 Windows 功能”，启用 **Windows Hypervisor Platform（Windows 虚拟机监控程序平台）** 后重启。

当前推荐 WHPX，不要照旧教程把 HAXM 当作必装项，也不要盲目关闭系统安全功能。

官方参考：[安装要求](https://developer.android.com/studio/install)、[硬件加速](https://developer.android.com/studio/run/emulator-acceleration)。

## 3. 安装 Android Studio 和 SDK

1. 从 [Android Studio 官方网站](https://developer.android.com/studio) 下载 Windows 安装程序，完成首次向导。
2. 建议保留默认 SDK 路径 `%LOCALAPPDATA%\Android\Sdk`，TTRS 会自动查找。
3. 欢迎界面打开 **More Actions → SDK Manager**；已有项目时使用 **Tools → SDK Manager**。
4. 在 **SDK Tools** 安装 **Android SDK Platform-Tools** 与 **Android Emulator**。
5. 在 **SDK Platforms** 勾选 **Show Package Details**，展开 **Android 9.0 (Pie) / API 28**。
6. 安装 **Google APIs Intel x86_64 Atom System Image**；不要选择 TV、Wear OS 或 ARM64 镜像，也不要把 SDK Platform 28 本身当成模拟器镜像。
7. 点击 Apply / OK，按需接受官方许可，等待下载结束。

本流程不需要 NDK、CMake 或 Android 源码。SDK 放在其他盘时记住 SDK Manager 显示的实际位置。

## 4. 创建 AVD

1. 欢迎界面进入 **More Actions → Virtual Device Manager**；已打开项目时使用 **View → Tool Windows → Device Manager**。
2. 点击 **+ / Create Virtual Device / Create Device**，选择手机类型的 **Pixel 3**。
3. 选择 **Android 9 / API 28 + Google APIs + x86_64**。根据需要调整 API 和 Services 筛选，不要直接选顶部推荐的最新 API。
4. 设备名可设为 `TTRS_API28`，其余参考下表，点击 Finish。
5. 在设备列表点击 ▶，等待 Android 桌面可以正常点击。

| 项目 | 建议值 |
| --- | --- |
| 硬件 | Pixel 3；Pixel 4 模板最低 API 要求更高，不作为 API 28 示例 |
| 镜像 | API 28 / Google APIs / x86_64 |
| CPU / RAM | 2–4 核 / 2–4 GB，按电脑资源分配 |
| Graphics | Automatic；黑屏或花屏时再尝试 Software 与 Cold Boot |
| 内部存储 | 8–10 GB |
| VM heap / 启动 | 256 MB / Quick Boot |
| 网络 | Speed: Full；Latency: None |
| 方向 / 相机 / SD 卡 | Portrait；其他保持默认，无需额外 SD 卡 |

**本配置无需另装 ARM 转译。** 当前指定兼容 APK 含 x86_64 地图、定位等原生库；更换只有 ARM 库的 APK 不能保证同样可用。

历史环境是 Google APIs x86_64 API 28 revision 11；其他 revision 或更高 API 不代表已完成相同兼容验证。若官方无法下载该镜像，请反馈，不要从不明来源获取修改镜像。

模拟器默认定位可能在美国。语言和时区不会自动修正 GPS，后面用 TTRS 的“预先定位”把位置设到路线起点。

参考：[官方 AVD 创建说明](https://developer.android.com/studio/run/managing-avds)。

## 5. 打开 TTRS 并连接设备

1. 保持 AVD 运行，打开 `软件\TTRS.exe`。
2. 在左侧“原生 AVD”区域刷新并选择设备。下拉框显示类似 `Pixel 3 · emulator-5554` 的机型和编号，不一定显示 AVD 名称；首次建议只开一台。
3. 在“步数兼容”区域点击 **检查**。
4. 需要指定兼容 APK 时点击 **安装 / 修复**。程序会校验自带文件并尝试覆盖安装，不会自动卸载应用。
5. 完成后再次检查，确认 **步数兼容版 v2 已就绪**。在模拟器内自行完成应用登录及定位授权。

若原版与兼容版签名不同，需要先处理要保留的数据，再决定是否手动卸载模拟器内原应用。**卸载会删除该应用的本地数据。**

第三方 APK 的权利与使用条件独立适用，参见 [分发说明](../NOTICE.txt)。

## 6. 配置高德地图

1. 登录 [高德开放平台控制台](https://console.amap.com/)，按平台要求注册或认证开发者。
2. 应用管理中创建应用，添加 Key。
3. 平台选择 **Web 端（JS API）**，不要选“Web 服务”或“Android”。
4. 取得同一条 Key 的 Key 和配套 `securityJsCode` 安全密钥；配额、开通要求及费用以高德控制台为准。
5. 在 TTRS **地图与高级设置** 中完整填写这组凭据。
6. 点击 **应用并重新加载地图**，等待道路、建筑底图出现。只有 Logo 和路线不代表瓦片成功。

以后更换 Key 仍需点击应用。不要公开带完整密钥的设置截图或个人配置目录。

参考：[申请 Key](https://lbs.amap.com/api/javascript-api-v2/prerequisites)、[安全密钥说明](https://lbs.amap.com/api/javascript-api-v2/guide/abc/jscode)。

## 7. 编辑路线

![TTRS 2.1.1 示例](assets/ttrs-2.1.1.png)

这是此前测试界面截图，未连接 AVD，不是你电脑的实时状态。

- 默认操场：点击 **恢复默认四点**，开启“闭合循环”和“椭圆跑道（4 点）”。
- 自定义路线：**清空默认四点 → 搜索自己的地点 → 按顺序点击地图加点**。搜索只移动地图，不会替换旧点；不清空就跨地区加点，会形成很长的连线。
- 可拖动标记调整位置，支持撤销、删除末点、反向与清空。
- 填写路线名后点击保存，下次从“保存的路线”选择。
- 不要操场曲线时取消椭圆模式。椭圆模式要求恰好 4 点。

开放路线至少 2 个不同点；闭合路线至少 3 点。**开放路线不能循环**，其长度应达到“目标距离 × 距离校准”，不够就延长路线或降低目标。

距离校准默认 1.03、采样间距默认 2 米，首次可保留默认值。目标距离、配速根据测试需要设置；实际结果以目标应用为准，校准和偏移等功能不保证任何平台接受记录。

地图与模拟器坐标转换自动处理；坐标列表统一为 WGS-84，本版没有手工坐标输入界面。

## 8. 每天怎么使用

1. 启动 AVD，等安卓桌面出现。
2. 打开 TTRS，刷新选设备，核对路线及兼容状态。
3. 点击 **预先定位**，到目标应用核对位置；位置不对先处理。
4. 在目标应用内开始测试，再点 TTRS 的 **开始模拟**。
5. 暂停会保留进度，继续接着运行；**停止结束发送并清空 TTRS 的实时进度面板**。
6. 在目标应用内自行暂停、结束和处理记录；TTRS 不会代为保存。

自然发送完成时保留最后统计，与手动停止不同。避免电脑休眠；不要同时播放 AVD Extended Controls 中的另一条定位路线。

## 9. 设置桌面快捷方式

AVD 配置好后，可直接启动，不必每天进入 Android Studio 设备列表。

桌面右键 → 新建 → 快捷方式，目标填入：

```text
"%LOCALAPPDATA%\Android\Sdk\emulator\emulator.exe" -avd TTRS_API28
```

示例假设 SDK 在默认目录、设备名是 `TTRS_API28`，不同则替换。把它命名为“启动 TTRS 模拟器”。

再右键 `TTRS.exe` → 显示更多选项 → 发送到 → 桌面快捷方式。

以后先开 AVD，等桌面，再开 TTRS。独立启动的 AVD 不需持续打开 Android Studio，但模拟器进程本身必须运行。移动 SDK 或程序目录后需更新快捷方式。

参考：[官方模拟器启动参数](https://developer.android.com/studio/run/emulator-commandline)。

## 10. 常见问题

| 现象 | 处理 |
| --- | --- |
| 没有找到 adb | 确认已装 Platform-Tools。非默认 SDK 路径可在 Windows 用户环境变量设 `ANDROID_HOME` 为 SDK 根目录（如 `D:\Android\Sdk`），完全退出再打开 TTRS。已有 `ANDROID_SDK_ROOT` 时两者不要指向不同 SDK。 |
| 设备列表为空 | 等安卓桌面后刷新；确认是原生 AVD、同一用户和 SDK。可 Cold Boot，先不要 Wipe Data。 |
| 找不到 API28 | 检查 Show Package Details、API / Services 筛选、机型的最低 API 限制。 |
| 卡顿、黑屏 | 核对虚拟化、WHPX、资源分配；仅开一台。试 Cold Boot，图形异常再试 Software。 |
| NO_MATCHING_ABIS | 核对指定 APK 与 x86_64 镜像，不要直接下载不明转译包。 |
| 签名冲突 | 先处理需保留数据，再决定是否手动卸载旧版；卸载将清除应用本地数据。 |
| 高德只有 Logo 和线 | 确认 2.1.1，重新应用同一组 Web JS API 凭据，并检查网络。 |
| 位置在美国 | 选正确 AVD，点预先定位，检查权限，并停止另一条定位路线播放。 |
| Console 鉴权文件缺失 | 同一 Windows 用户重新正常启动 AVD，不要公开 token 或关闭认证。 |
| EXE 无法单独运行 | 完整解压，保留所有文件；创建快捷方式而非移动 EXE。 |
| TTRS 停止后目标应用仍计时 | 两个软件状态独立，还要在目标应用内暂停或结束。 |

高德错误码：`INVALID_USER_KEY` 检查 Key；`INVALID_USER_SCODE` 检查配对安全码；`INVALID_USER_DOMAIN` 检查绑定域名规则；`USERKEY_PLAT_NOMATCH` 检查是否误选服务平台。[官方错误码](https://lbs.amap.com/api/javascript-api-v2/guide/abc/errorcode)。

系统拦截或报毒时，先核对发布来源及校验值，再反馈原始提示，不要直接关闭安全软件。

## 11. 更新与反馈

更新前完全退出旧 TTRS，再把新版完整解压到新目录。同一 Windows 用户下通常继续使用原配置，不要删除 AppData 应用配置。换电脑或用户不等于迁移路线，本版没有界面化导入导出。

反馈时提供 TTRS、Windows、Android Studio / Emulator 版本、AVD 的 API / Services / ABI，以及错误文字和遮盖隐私后的截图。不要提供登录密码、完整地图 Key、安全密钥、Console token 或个人模拟器镜像。

程序 ZIP 内附带有目录和界面示例的 `使用教程.html`，解压后可离线阅读，也可用浏览器打印为 PDF。地图和相关联网服务仍需网络。
